AI-native engineering: MCP server and spec-first agent workflow

A remote MCP server that lets teammates query, explain and simulate live segmentation rules from Claude, and how I build spec-first with AI coding agents.

Context

I build backend and platform work with AI coding agents, spec-first and test-first, and I gave teammates a way to work with the live player-segmentation rules from Claude. The diagram shows both: the chain every change runs through, from a written spec to a commit, and the side lane from Claude through the remote MCP server to the segmentation service.

My role

I built the remote MCP server, and I shipped the scoring pipeline and dashboard for an early-payer prediction model. I also mentored a junior engineer through code review.

What I built

  • I built a remote MCP server that lets teammates query, explain and simulate live segmentation rules from Claude.
  • I kept it read-only, OAuth-protected and allow-listed, so teammates can look into the live rules from Claude but never change them through it.
  • I shipped the scoring pipeline and dashboard for an early-payer prediction model.
  • I work spec-first and test-first with AI coding agents in Claude Code. Every change runs the same chain: a written spec, a written plan, the tests first, the implementation by the agents, review, then a commit.
  • I mentored a junior engineer through code review.
