Platform & AI

Player-segmentation service and admin console

The rule engine that decides which economy and ad configuration each Hexa Sort player receives, and the secure console teams use to manage its rules.

Context

Hexa Sort decides which economy and ad configuration each player receives through segmentation rules, and Product and UA teams author, preview and publish those rules themselves. The diagram follows both paths through the service I built: a player’s request down to the rule engine and back, and a rule change up from the admin console.

My role

I designed and built the service end to end: the rule engine, its data layer and request logging, and the secure admin API and web console on top of them.

What I built

  • I built a data-driven rule engine in Node.js, TypeScript and Express that decides which economy and ad configuration each player receives.
  • I migrated the data layer twice without changing live behaviour, from JSON files to MySQL and then to PostgreSQL on Google Cloud SQL, with golden-corpus parity tests gating each step.
  • I moved request logging onto a queue on Redis and BullMQ, with a kill switch, a depth guard and scheduled retention.
  • I built a secure admin API and web console in React, TanStack Start, Tailwind and Zod, so Product and UA teams author, preview and publish rules themselves. It uses OAuth 2.0 with PKCE, JWT, CSRF protection, rate-limited login and audit logs.
  • I added a rule-impact preview that shows the before/after player distribution before a change goes live.
